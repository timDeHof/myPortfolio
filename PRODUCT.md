# Product

## Register

brand

## Platform

web

## Users

Hiring managers and technical recruiters evaluating Tim DeHof for engineering roles. They arrive with a resume or referral, scan for 30–60 seconds, and make a gut decision: is this person worth an interview? The portfolio must answer "yes" by showing real work, clear thinking, and technical credibility — without making them dig.

## Product Purpose

A personal portfolio that converts passive visitors into active conversations. It exists to prove that Tim builds scalable, well-architected web applications — and makes the case visually, through real projects and tangible outcomes, not claims.

## Positioning

Clean code, real impact. Every screen reinforces that this is a developer who writes maintainable architecture and ships things that solve actual problems.

## Conversion & proof

- **Primary CTA**: Browse Projects — the portfolio's proof lives here. Every project should reduce friction between "I'm curious" and "I've seen enough."
- **Secondary CTA**: Let's Talk — contact form for visitors ready to reach out.
- **The line a visitor remembers after 10 seconds**: "I build things that work, and I can prove it."
- **Belief ladder**: (1) He's a real developer with real projects → (2) His code is clean and well-structured → (3) His work produces measurable results → (4) He'd be a strong addition to my team
- **Proof on hand**: Testimonials section on the About page, certifications section, GitHub integration showing activity. No external proof assets on hand yet.

## Brand Personality

**Approachable · Reliable · Modern.** The tone is warm but professional — someone you'd trust on a team. Not aggressive, not flashy, not trying too hard. Confidence comes from the work, not from the presentation.

## Anti-references

Avoid overly flashy dev portfolios: particle effects, glitch transitions, neon-on-black, "look at me" scroll hijacking, and anything that prioritizes showing off over communicating substance. Also avoid generic SaaS landing pages with cream backgrounds and gradient text — that's a different failure mode.

## Design Principles

1. **Show, don't tell** — Let the projects and code speak. Every claim should be backed by something visible.
2. **Approachable reliability** — Warm enough to feel human, polished enough to feel professional. Neither cold-corporate nor casual-sloppy.
3. **Clean code philosophy** — The portfolio itself should embody the clean architecture it promotes. If the code is messy, the message is hypocritical.
4. **Modern but grounded** — Use current tools and patterns (React, TypeScript, Tailwind) without chasing trends that date quickly.
5. **Respect the visitor's time** — Hiring managers scan. Put the strongest proof above the fold. Make navigation effortless.

## Accessibility & Inclusion

WCAG 2.1 AA compliance. Keyboard navigable, screen reader friendly, proper contrast ratios, reduced motion support already implemented via `prefers-reduced-motion` media query and Framer Motion's `useReducedMotion` hook.
