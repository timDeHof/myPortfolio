Shop floor: scrapped parts, downtime

Root cause first.

On a production line, a fix that skips the root cause comes back on the next shift. I trace bugs through every layer, from the UI to the query, before changing code.

Shop floor: tolerances

Design for the constraint.

Parts have tolerances, and software has budgets: load time, accessibility, the next developer's time. I decide which constraint matters before choosing a tool.

About

Seven years in manufacturing. Now full-stack.

I'm a full-stack engineer in Jacksonville, FL. Before software, I spent seven years as a mechanical engineer in manufacturing and 3D printing.

How I got here

The habits carried over

In manufacturing, a problem on the line had a cost you could count: scrapped parts, downtime, a missed shipment. I learned to measure before changing anything, to find the root cause instead of the nearest symptom, and to document work so the next shift could pick it up.

What pulled me toward software was the 3D-printing software itself. The first time I used it, I saw how much of our production process it could streamline.

In 2022 I finished Fullstack Academy's full-stack web development bootcamp and started building full-time. Since 2024 I've been a Frontend Engineer at TeamForward, building an event-planning and networking platform in React, TypeScript, and Tailwind CSS. Since 2026 I've also taken contract work through Jokma Web Solutions.

I still measure before I optimize, trace bugs to their source, and write code for whoever maintains it next.

How I work

Four practices

Measure, then change.

Before optimizing anything, I find out where the time actually goes, whether that's a slow query, an oversized asset, or a render-blocking request.

Understand existing code before touching it.

Most work happens in codebases someone else started. I read what's there and why before proposing changes.

Accessibility is part of done.

I build accessibility in from the start instead of auditing it at the end. At TeamForward I keyboard-test each interface I build, and I took W3Cx WAI0.1x: Introduction to Web Accessibility.

Write for the handoff.

Clear pull requests, small commits, and docs that answer the question the next developer will actually ask.
